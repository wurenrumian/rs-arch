前六章按部件讲「为什么这样设计」。这一章换成另一种读法：不切部件，只跟一条请求，从训练进程里的第一行代码，一路跟到存储引擎里的最后一次拷贝。目标很具体——你拿到一个现象或一个改动，能在几分钟内定位到该读哪个文件、哪个函数。

## 6 个站

| 站 | 你面对的东西 | 这一站回答 | 主入口 |
|---|---|---|---|
| 1 | 模型代码 | 这一批要哪些 id | 前向模块 |
| 2 | Python 门面 | id 怎么归一化、怎么编码 | `KVClient` |
| 3 | op 运行时 | 缓存查不查、后端是谁 | `recstore_ops` |
| 4 | PS 客户端 | 按哪个分片、怎么切块、走哪条传输 | `BasePSClient` |
| 5 | 服务端编排 | 找表、校验、交给优化器还是引擎 | `CachePS` |
| 6 | 存储引擎 | key 换句柄、句柄换字节 | `KVEngineComposite` |

一句话关系：1→2→3→4 都在训练进程，4 到 5 是唯一一次跨进程，5→6 是服务进程里的普通调用。这一章每一页只跟其中一段，页尾给出下一段的入口。

## 核心概念表

| 概念 | 一句话 |
|---|---|
| 门面 | Python 侧唯一对外的客户端对象，全进程一个 |
| op 运行时 | C++ 侧的单例，持有 PS 客户端，负责校验与缓存分流 |
| 分片客户端 | 按 key 哈希把一批拆成每分片一份，并发发出 |
| 编排层 | 服务端的 `CachePS`：找表、校验学习率、决定走优化器还是引擎 |
| 两次翻译 | 索引把 key 换成句柄，值存储把句柄换成字节 |
| tag | 拼在 key 高 8 位的表号与角色，让存储层不必认识「表」 |
| 判据 | 每个分叉点真正做决定的那个条件，定位时先看它 |

## 怎么用这一章

1. 先读你关心的那条路线，不要按顺序读三页。
2. 每页的「入口 → 判据 → 出口」表就是断点位置：把断点下在入口，单步跟到出口，中间不要跳。
3. 跟丢时回到[定位手册](./locator)，按现象查，而不是按目录猜。

代码按上游 `upstream/main` 的 `a1cfcc81f` 核对。路径都相对仓库根，符号用 `#` 分隔。

## 范围与不在范围

在范围内：训练侧到存储引擎的读、写、启动三条主路径，以及每条路径上的分叉判据与代码入口。不在范围：BagPipe 与 GPU 缓存的驻留策略（第 02 章）、RDMA 槽位协议的字节布局（第 04 章）、测试与基准的运行方式（第 06 章）。这三块各有专页，本章只在分叉点指出「这里改走另一条路」。
