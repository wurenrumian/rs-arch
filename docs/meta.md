# 生成方式与版本基线

## 版本基线

正文按 RecStore 上游 `upstream/main` 的 **`1f340167d`** 核对。代码继续往前走之后，
结论不会自动失效，但需要对照每章末尾的证据索引复核一遍。

## 写作方式

六章都用同一套节奏：先给**阅读地图**（一句话、部件表、关系、概念表、建议读法），
然后一块一块推进。一块只回答一个问题，讲完给一句“交付一句”，指出下一块接什么。

这样组织的代价是重复：同一个类型在相邻两章各出现一次。好处是任何一页都能单独读，
不必先读完前面五百行。

## 内容从哪来

最初是六份单文件长文档（每份 400–600 行），按上游提交逐段核对写成。这次拆成按块一页，
正文内容不变，只做三件事：拆页、把 `###` 提升为页内章节、把跨章引用改成可点的链接。

## 证据约定

- 正文用 `相对路径#符号`（类 / 函数 / 宏 / 字段），**不引用行号**：行号会随提交漂移。
- 每章末尾有**证据索引**，列出该章引用的文件与符号；改动代码后照它复核。
- 推断与待验证的结论显式标出，统一收在[未确认清单](/quality/unknowns)。
- 上游 `docs/` 与代码的冲突集中在[文档不一致](/quality/doc-gaps)。

## 站点怎么跑

```bash
npm install
npm run dev      # 本地预览，默认 base 为 /rs-arch/
npm run build    # 产物在 docs/.vitepress/dist
npm run preview
```

想换子路径（比如本地用根路径），设置环境变量即可：

```bash
VITEPRESS_BASE=/ npm run build
```

站点部署在 rumian 的聚合服务上，挂在 `/rs-arch/` 子路径，产物由那边的聚合站点直接托管。新增子站要改两处：

| 要改的地方 | 位置 |
| --- | --- |
| 站点清单 | `sites/server.js` 的 `SITES` 表 |
| 首页元数据 | `home/index.js` |

图在**构建期**就画好了：`docs/.vitepress/diagrams.ts` 把每个 mermaid 代码块交给 [pele](https://pele.run)
同步渲染成内联 SVG，页面不加载任何图表运行时——切主题也不用重画，配色走 `--pele-*` 那几个 CSS 变量。
图里语法写错会让构建直接失败，报出文件与正文行号。

## 目录结构

```text
docs/
  index.md                 首页
  guide/                   阅读指南、核心事实、代码索引
  ch01 … ch06/             六章：每章一个地图页 + 每块一页 + 风险 + 证据索引
  quality/                 风险总表、已修复、文档不一致、未确认清单
  .vitepress/              配置、主题、自定义样式、图表渲染
  public/                  logo 与首页插图
```
