# 术语表

正文只用**概念名**：短中文短语，或者单个英文词（比如 lane）。类名、函数名、配置键、字段名统一收在每页的「代码位置」表里，不混进叙述句。

同一个东西全站只有一个叫法。查手册时按这张表对名字，比按记忆搜关键词可靠。

## 跨章通用

| 概念 | 一句话 | 代码里的名字 |
| --- | --- | --- |
| 分片 | 一份独立持有的表数据，路由的最小单位 | shard、`num_shards` |
| 载荷 | 一次请求除头部之外要传的数据 | payload |
| 压缩块 | 线上传的一行：定长头带 key 与维度，后面紧跟 float 数据 | `ParameterCompressItem` |
| 批 | 一次调用里带上来的那组 key 及其数据 | batch |
| 上限 | 单次调用或单块允许的最大量，超过就切 | `MAX_PARAMETER_BATCH`、`max_keys_per_request` |
| 学习率 | 优化器的步长；客户端上报、服务端裁决 | `learning_rate` |
| checkpoint | 把内存里的表存到磁盘、之后再读回来的那件事 | `SaveCheckpoint`、`LoadCheckpoint` |
| 完成事件 | 一次异步写或读做完之后，由网卡交回的通知 | CQE |
| 就绪 | 对端可以安全接收请求的状态或信号 | READY、`kRcSlotDone` |
| 对端 | 这次请求的另一头：客户端说服务端，服务端说客户端 | peer |

## 第 03 章：参数服务器与传输

| 概念 | 一句话 | 代码里的名字 |
| --- | --- | --- |
| 请求 | 一次批量读写调用，带表名、key 数组和可选的值或梯度 | `BasePSClient::GetParameter` 等 |
| 分片层 | 负责路由、切块、并发扇出与结果回填的外壳 | `DistributedShardedClient` |
| 单分片客户端 | 只连一个分片的传输实现 | `GRPCParameterClient`、`BRPCParameterClient` |
| 命令 | 协议里除读写之外的入口：清空、重载、灌假数据、存取 checkpoint | `Command`、`PSCommand` |
| 槽位 | 共享内存里一块定长的请求 / 响应缓冲区 | slot、`LocalShmSlotHeader` |
| 槽位头 | 槽位开头那段描述本次请求的定长头 | `LocalShmSlotHeader` |
| 提交步 | 稀疏更新的「会话 + 步号 + 分块」三元组，去重的依据 | `SparseGradientCommitHeader` |
| 线程号 | 传给存储层的线程身份，决定用哪组内部资源 | `tid`、`ready_queue_id` |

## 第 04 章：RDMA 传输

| 概念 | 一句话 | 代码里的名字 |
| --- | --- | --- |
| lane | 一条独立的 RC 连接，连同它独占的设备、队列与内存注册 | lane、`RcShardClientTransport` |
| 槽位 | lane 上一块按固定偏移切好的注册内存，请求与响应各占一半 | slot |
| 描述符 | 请求开头那 192 字节，写明这次要读什么、写什么 | `RequestDescriptor` |
| 提交字 | 客户端最后单独写的一个 64 字节控制字，表示「请求已就绪」 | `CommitWord` |
| 状态字 | 服务端最后单独写的一个 64 字节控制字，表示「结果已就绪」 | `StatusWord` |
| 控制字 | 提交字与状态字的合称 | `CommitWord`、`StatusWord` |
| 世代 | 一次重建的编号，用来挡住旧连接的迟到完成 | `lane_generation`、`epoch` |
| 脏 | lane 暂时不可用，等待者立刻失败而不是阻塞 | dirty |
| 置脏 | 把一个 lane 标成「脏」这个动作 | `MarkLaneDirty` |
| 回退 | 行无法直接寻址时，整批改走拷贝路径 | fallback |
| 控制面 | 只交换连接元数据与健康状态的旁路服务，不进读写热路径 | `RdmaControlPlaneServer` |
| 内存注册 | 把一块内存交给网卡，之后网卡才能直接读写它 | MR、`ibv_reg_mr` |

## 容易混的两组

**分片层 vs 单分片客户端**：分片层决定「这个 key 去哪个分片、怎么切块、结果怎么拼回来」；单分片客户端只管「把这一块发给那一个分片」。前者调后者，方向不能反。

**提交字 vs 状态字**：方向不同。提交字由客户端写、服务端读，意思是「请求放好了」；状态字由服务端写、客户端读，意思是「结果放好了」。两者都是 64 字节，都靠连接保序当作屏障。

## 与上游文档的差异

上游文档（`docs/`）里有几处把同一件事写成两个词（例如槽位的中英文混用、把自动取值 `auto` 列成运行时可选项）。本站正文按上表统一；上游原话只在「文档不一致」页里出现。
